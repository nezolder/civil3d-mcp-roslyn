### Windows test failure

**Proven:** `tests/skills/skills-run-by-name.test.mjs:194` compares the generated `compare_surface_elevations` prefix with a literal containing LF line endings:

```text
AssertionError [ERR_ASSERTION]:
assert.ok(sentRead.code.startsWith('var surfaceAHandle = "1A";\nvar surfaceBHandle = "2B";\n' + ...))
```

The generated prefix contains the expected bound values, but preserves the template's Windows CRLF line endings. The literal comparison is false; after replacing CRLF with LF, the same prefix comparison is true. All 31 tests pass when the exact same commit is checked out with LF. This is a reproducible test portability issue. The assertion should normalize line endings or compare the declarations without requiring a particular newline sequence. Production source and tracked tests were not changed for this retest.
